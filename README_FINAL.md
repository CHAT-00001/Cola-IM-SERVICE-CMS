## 🏗️ 架构亮点

### 一、六边形架构 (Hexagonal Architecture)

```
┌─────────────────────────────────┐
│   外层：Web/CLI/Message Queue    │
│   (Actix-web, CLI tools)        │
└──────────────┬──────────────────┘
               │
┌──────────────▼──────────────────┐
│ 中层：API/Gateway 接口          │
│ (请求解析、参数验证)            │
└──────────────┬──────────────────┘
               │
┌──────────────▼──────────────────┐
│ 核心：业务逻辑层 (Case)         │
│ (流程编排、决策逻辑)            │
└──────────────┬──────────────────┘
               │
┌──────────────▼──────────────────┐
│ 端口与适配器层                   │
│ ┌────────┐  ┌────────┐          │
│ │ Port   │  │Adapter │          │
│ │(Trait) │◄─┤(Impl)  │          │
│ └────────┘  └────────┘          │
└──────────────┬──────────────────┘
               │
┌──────────────▼──────────────────┐
│ 数据层：Repository/Service      │
│ (PostgreSQL, Redis, HTTP API)  │
└─────────────────────────────────┘
```

### 二、分层清晰性

| 层级 | 职责 | 示例 |
|------|------|------|
| GATEWAY | 请求入口、会话验证 | Actix 路由处理 |
| API | 权限编排、响应格式化 | AppData<T> 统一壳 |
| CASE | 业务逻辑编排 | 购买流程、点赞逻辑 |
| PORT | 接口定义 (trait) | BuyAddPort, LikeCheckPort |
| ADAPTER | trait 实现 | BuyAddPortAdapter |
| REPOSITORY | 数据存储 | DB、Cache、Service 调用 |

### 三、Port Adapter 特性

✅ **每个 trait 独立文件** - 便于并行开发
✅ **单一职责原则** - 一个文件一个 trait  
✅ **易于测试** - 可独立进行单元测试
✅ **易于扩展** - 新增功能只需新增文件
✅ **代码复用** - 同一 adapter 被多个上层调用
