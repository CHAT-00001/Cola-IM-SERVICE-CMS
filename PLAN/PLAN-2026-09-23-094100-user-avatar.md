## 📋 项目概述

为用户网关补齐用户资料维护及头像、昵称历史管理能力，并统一 UGC 用户头像的 CDN URL 解析。用户资料相关 API 与 CASE 集中在 `cola_user` 的 `user` 子目录，与 `role` 等功能模块分离。

### 核心约定

- 用户资料 API：`cola_user/src/api/user`
- 用户资料 CASE：`cola_user/src/case/user`
- 不将上述接口放入 `role` 模块；其他分层遵循当前仓库已有的用户模块组织方式。
- 用户头像路径在数据库和缓存中始终保留原始值；仅在构造对外响应时解析 CDN URL。
- 所有用户自助写操作以可信会话中的 UID 确定数据归属，不信任请求体或 URL 中客户端传入的 UID。
- 保留 `gate_http/src/router_v2/user/gateway.rs` 已有未提交改动，不覆盖或回滚。

---

## 🎯 功能范围：9 个接口

### 用户资料维护（3 个）

1. **修改头像**：更新当前用户头像路径，并按既有业务约定维护头像历史。
2. **修改昵称**：更新当前用户昵称，并按既有业务约定维护昵称历史。
3. **修改用户资料**：更新允许用户自行编辑的资料字段；字段白名单及校验遵循现有用户资料模型。

### 头像历史（3 个）

4. **查询头像历史**：仅返回当前会话 UID 所属记录，遵循项目的分页和排序惯例。
5. **启用头像历史项**：仅允许当前用户启用自己的有效历史记录，并同步更新当前头像资料。
6. **逻辑删除头像历史项**：仅逻辑删除当前用户自己的历史记录，不物理删除数据。

### 昵称历史（3 个）

7. **查询昵称历史**：仅返回当前会话 UID 所属记录，遵循项目的分页和排序惯例。
8. **启用昵称历史项**：仅允许当前用户启用自己的有效历史记录，并同步更新当前昵称资料。
9. **逻辑删除昵称历史项**：仅逻辑删除当前用户自己的历史记录，不物理删除数据。

> 具体 URL、请求/响应 DTO、历史表字段和异常码在实现前应以现有 API、用户资料模型及迁移约定为准；不得因此改变上述 9 项功能边界或目录归属。

## 🗂️ 分层与目录规划

### API 与 CASE

- 在 `cola_user/src/api/user` 定义资料修改、历史查询、启用和逻辑删除 API/DTO。
- 在 `cola_user/src/case/user` 实现对应业务用例。
- 更新 `cola_user` 的模块声明与导出，使新模块可以通过既有路由/网关链路调用。
- 与 `role` 等模块保持边界清晰，不把用户资料或历史操作挂入 `api/role`、`case/role`。

### 数据与持久化

- 在 `cola_data` 增加所需的 entity、info、command/query DTO，遵循相邻用户功能的命名与序列化约定。
- 在 `port` 定义用户资料/历史所需的仓储接口。
- 在 `repo_adapter` 实现接口适配，并遵循项目现有的缓存失效或 cache-aside 策略。
- 在 `repository` 实现数据库查询与更新，查询/更新均需带 UID 条件以落实数据归属隔离。
- 增加数据库迁移，支持头像与昵称历史记录、启用状态及逻辑删除；索引应覆盖 UID、记录状态及常用排序字段。
- 将新建接口与服务注册到现有 `AppContext` / 路由体系，具体注册位置按仓库实际结构确定。

## 🖼️ 头像 CDN URL 解析

### 规则

- 默认 CDN 域名：`https://cdn1.damawei.com`。
- 空值保持不变。
- 完整 URL（包括 `http://`、`https://`）保持不变，避免重复拼接。
- 相对路径拼接 CDN 域名；正确处理路径前导 `/` 与域名末尾 `/`，避免产生双斜杠或缺少分隔符。
- `None` 仍为 `None`；不得把空头像变成 CDN 根路径。
- 数据库与缓存中仅保存原始头像路径，不保存拼接后的 CDN URL。

### CDN 配置切换

- 解析能力应可复用，并支持根据头像 bucket 的 `app_id` 查询 CDN 配置。
- CASE 通过现有 bucket Port 查询 `BucketInfo.cdn_domain`，把解析后的域名传递给资料组装逻辑；不要让没有 `AppContext` 的 assembler 直接访问 Port。
- 项目已有按 `app_id` 查询 bucket 的能力，以及视频 CASE 的 CDN 解析模式，可作为实现参考。
- 头像 bucket 的具体 `app_id` 尚未在代码中确认；实现时应集中定义或通过配置传递，不在多个 assembler 中散落硬编码。bucket 未配置 CDN 时回退到 `https://cdn1.damawei.com`。

### UGC 输出接入

- 在通过用户资料查询并组装响应的链路应用头像 URL 解析，至少检查 UGC 视频作者资料、评论用户资料及其他复用 `UserInfo` 的 UGC 输出。
- 仅转换即将对外返回的头像字段，不修改持久化对象或缓存对象中的原始路径。
- 检查所有相关列表和单项响应，避免只覆盖其中一种组装入口。

## 🔐 安全与一致性要求

- 可信 UID 来自已验证的会话上下文；请求 DTO 不应允许通过 UID 覆盖会话身份。
- 查询、启用、删除 repository 操作必须同时约束记录 ID 与 UID，防止越权访问其他用户历史。
- 启用历史项与更新当前资料应保持一致；根据现有数据库能力使用事务或等价的一致性处理。
- 逻辑删除后的历史项不能再被启用；重复启用、删除不存在记录应遵循项目既有的错误语义。
- 用户昵称、头像及资料字段的验证遵循现有约束，不额外暴露敏感字段。

## ✅ 测试与验收

### 用户资料与历史接口

- 覆盖 9 个接口的成功路径、参数校验、记录不存在及数据库错误路径。
- 验证会话 UID 被用于所有读写；构造其他 UID 的记录 ID 时不得读取、启用或删除他人数据。
- 验证历史逻辑删除后仍保留记录，且不能再被启用。
- 验证头像/昵称历史项启用后，当前用户资料同步更新。

### 头像 URL 解析

- 空字符串保持空字符串；`None` 保持 `None`。
- 完整 HTTP/HTTPS URL 不变。
- 带前导斜杠和不带前导斜杠的相对路径均拼接正确。
- 自定义 bucket CDN 域名生效；域名末尾斜杠不会产生重复分隔符。
- bucket 或 CDN 配置缺失时使用 `https://cdn1.damawei.com`。
- 验证 UGC 视频、评论等资料响应使用转换后的 URL，而数据库/缓存仍保留原始路径。
